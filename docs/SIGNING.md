# Подпись программы для Windows

Почему Windows ругается: exe не подписан, поэтому Windows не знает, кто его выпустил:
«Неизвестный издатель» в окне UAC и синее окно SmartScreen «Windows защитила ваш компьютер»
при запуске скачанного файла. Подпись решает первое сразу. Второе снимается, когда у издателя
накопится «репутация» (подписанный файл скачали и запустили достаточно раз) — или сразу, если
программу распространяет Microsoft Store.

Сборка уже умеет подписывать (`desktop/scripts/build.mjs`, `.github/workflows/release.yml`):
нужен только сертификат. Без него всё собирается как раньше, неподписанным.

## Варианты

| Вариант | Цена (ориентир, проверить на сайте) | Кому не будет предупреждения | Что нужно сделать |
|---|---|---|---|
| **Самоподписанный** (`desktop/scripts/make-dev-cert.ps1`) | бесплатно | только на компьютерах, где сертификат установлен как доверенный | запустить скрипт, установить `.cer` на свои ПК |
| **Azure Trusted Signing** (облачная подпись Microsoft) | ~10 $/мес. | всем: издатель подтверждён Microsoft, репутация копится быстро | аккаунт Azure, проверка личности; для частных лиц сервис был доступен не во всех странах — проверить |
| **Обычный сертификат OV** (Certum, Sectigo, SSL.com…) | ~100–400 $/год | «Неизвестный издатель» уходит сразу; SmartScreen — по мере репутации | покупка, проверка личности; ключ теперь выдаётся только на токене/в облаке (с 2023 г.) |
| **Microsoft Store** (пакет MSIX) | разовый взнос разработчика | всем: пакет подписывает сам Store | аккаунт разработчика, публикация в Store (отдельная сборка `appx`) |

Сертификат EV с 2024 года больше не даёт мгновенного доверия SmartScreen — переплачивать за него
ради этого не нужно.

## Самоподписанный — для своих компьютеров

```powershell
cd desktop
powershell -ExecutionPolicy Bypass -File scripts\make-dev-cert.ps1 -Trust
$env:CSC_LINK = "$PWD\certs\blackbox-studio-dev.pfx"; $env:CSC_KEY_PASSWORD = "<пароль>"
npm run dist
```

`-Trust` добавляет сертификат в «Доверенные корневые» и «Доверенные издатели» текущего
пользователя — Windows спросит подтверждение. На другом своём компьютере установить
`certs\blackbox-studio-dev.cer` так же. Папка `desktop/certs/` в git не попадает; `.pfx` — это
ключ, никому не отдавать. Друзьям этот вариант не поможет: у них сертификат не установлен.

## Подпись в GitHub Actions

Settings → Secrets and variables → Actions → New repository secret:

- сертификат-файл (`.pfx`): `WIN_CSC_LINK` — содержимое `.pfx` в base64
  (`[Convert]::ToBase64String([IO.File]::ReadAllBytes('файл.pfx'))`), `WIN_CSC_KEY_PASSWORD` — пароль;
- Azure Trusted Signing: `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`,
  `AZURE_SIGN_ENDPOINT` (например `https://weu.codesigning.azure.net`), `AZURE_SIGN_ACCOUNT`,
  `AZURE_SIGN_PROFILE`, `AZURE_SIGN_PUBLISHER` (точно как CN в сертификате профиля).

Шаг «Проверка подписи» в прогоне печатает статус подписи каждого exe; в релизе рядом лежит
`signing.txt` — чем подписано. Самоподписанный сертификат в секреты класть смысла нет: у
скачавших он не доверенный.
